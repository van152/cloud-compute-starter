# Session capability follow-up — 2026-11-13

This follow-up adds information available from safe host probes after the initial audit. It supersedes only the earlier statement that the CPU model could not be resolved. It is not an inference benchmark and does not claim tokens per second.

- OS/kernel: Linux 6.18.57, x86_64.
- CPU: Intel Xeon Platinum 8573C; 9 CPUs visible to the process.
- Memory: 10,206,468 KiB total, 9,558,548 KiB available at the snapshot; no swap.
- Workspace filesystem: 67,586,535,424 bytes total, 64,087,121,920 bytes free.
- Cgroup CPU and memory limits were not readable from the standard v1/v2 locations, so a quota/limit cannot be reported.
- No accelerator device paths were present: /dev/nvidia0, /dev/kfd, and /dev/dri were absent. nvidia-smi, rocm-smi, and rocminfo were unavailable.
- Python 3.12.14. No installed torch, transformers, safetensors, accelerate, huggingface_hub, vLLM, SGLang, Triton, or llama-cpp-python distribution was found.
- No Hugging Face or Torch model cache was present.

## Conclusion

This container cannot run Qwen3-MoE-Tiny inference as inspected: there is no accelerator exposed, no PyTorch/Transformers or serving runtime, no model cache, and no configured inference endpoint. No packages were installed and no weights were downloaded. Therefore no speed result was produced.

The useful next step is to run the dependency-free preflight on a model-capable compute image. The Transformers runner can measure a local model process; the new API runner can compare vLLM/SGLang-compatible endpoints when available. A server benchmark must retain the same host, model revision, request shape, concurrency, and server settings for a valid comparison.

## Provenance

The snapshot is generated by preflight.py from /proc, process CPU affinity, cgroup files, filesystem capacity, Python package metadata, and accelerator path/tool availability. It omits hostnames, IPs, environment-variable values, prompts, and credentials.
